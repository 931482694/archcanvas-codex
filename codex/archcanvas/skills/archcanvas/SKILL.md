# archcanvas：项目架构画布

所有工具的 `project` 均传当前项目根目录的绝对路径。工具描述提供字段结构；不得为找工具改用户全局配置。

用户提示钩子给出了“本会话 archcanvas session_id”时，调用工具时原样传入该 `session_id`。不能用项目共享 context 中最后一个会话冒充调用者；没有可靠标识时只使用当前 MCP 连接身份，重启连接后旧的匿名待办需要用户取消后重新交付。

## 打开与画图

- 用户要看画布：`open_canvas`，给出返回的本机链接。浏览器请求在用户下一条消息里附带，不能声称 Codex 已收到并开始实施。
- 首次生成：先读入口和源代码，再 `save_graph`。3–6 个分组、5–40 个模块；列真实文件、模块类型和代码依据（文件与行号）。写 1–3 条执行主线 `flows`，每条 5–15 步；调度模块只在开头列一次。找不到依据就留空，不编造。
- 代码结构发生局部变化：`read_graph(brief: true)` 查 id，再 `update_graph`，只传变化。例如 `change_nodes: [{id: 'reports', add_files: ['src/export.py']}]`。模块内部的实现变化不必重画整图。
- 完整重画才用 `save_graph`。结构变化会等待用户在画布上确认；工具说“待确认”时不能声称新图已经生效。用户设置和敏感标记由工具保护。
- 要说明、连线、依据和代码核对详情：`read_graph` 不传 brief。代码依据在文件中移动时，读取返回当前行号。

## 已交付待办

1. `list_tasks`，只处理已交付事项，草稿不算授权。沿用用户在本会话已有的实施授权；需要新增范围或不可撤回动作时先确认。
2. 动代码前 `start_task(id)`；同一项目同时只实施一项待办，其他会话的事项不能误完成。
3. 实施并完成能自行运行的验证。
4. `complete_task(id, summary, files?, node_id?, sources?)`；新增模块提供真实文件。工具返回完成后才说完成，可重试相同完成调用。
5. 缺数据、缺决定或无法继续：`release_task(id, reason)`，放回用户草稿，已有代码保留。不要通过 complete_task 冒充完成。

## 人工测试与结果

- 自己无法验证的行为：`request_check(nodes, title, steps, expect, paths)`。步骤必须具体；可自行跑的测试不要转交用户。
- 用户测试后：`list_checks` 查看反馈，失败事项可由用户在画布上转成待办草稿。
- 分析或测试形成关键结论：`record_result(summary, files)`，只记录汇总数字和结论，不写姓名、病历号或个体数据。文件路径相对于项目。

## 敏感数据与记录限制

数据默认敏感，只看目录；只能由用户在画布中确认不敏感。不要读取、搜索展示或打印敏感数据，也不要换命令绕过已信任钩子的拦截。运行处理脚本时只输出汇总，报错不要带出个体记录。读取带敏感输出的 Notebook 前，先由用户在画布清掉输出。

**Codex 命令原始输出不会被此插件自动替换或打码。** 设置只过滤保存的工作记录；读取拦截依赖已信任的钩子和可识别的命令，不构成文件权限隔离。不能承诺所有写法都被拦截。

修改历史与任务快照在项目 `.archcanvas/` 内。钩子捕获的命令只保存摘要，不存原始输出；缺少退出状态显示未确认。没有 Stop hook，无法可靠记录最后回复和精确结束时间；下一条要求封存上一条为“没有结束记录”。本机 Codex 宿主安装和信任状态需要单独实测。
